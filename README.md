# algo-portfolio · ОП.04 «Основы алгоритмизации и программирования»

Ваш репозиторий на всю дисциплину: решения задач, тесты к ним и заметки о том,
сколько решение стоит по времени и памяти. Здесь же лежат конспекты занятий
и файлы, которые раздавались на парах. К концу курса репозиторий становится
портфолио, которое можно показать на собеседовании.

## С чего начать

**1. Сделайте репозиторий своим.** Нажмите **Use this template → Create
a new repository** и назовите его `algo-portfolio`. Кнопка **Fork** для этого
не подходит: форк остаётся привязан к исходному репозиторию.

**2. Откройте репозиторий у себя.** Нужен **Python 3.12**, на Windows при
установке отметьте галочку *Add Python to PATH*. В VS Code: **Source Control →
Clone Repository**, вставьте адрес своего репозитория и выберите папку.
Как это выглядит по шагам — [разбор с кадрами](docs/git/README.md#2-первый-репозиторий).

**3. Соберите окружение.** Команды различаются по системам:

| Шаг | macOS / Linux | Windows (PowerShell) |
|---|---|---|
| создать окружение | `python3 -m venv .venv` | `py -m venv .venv` |
| активировать | `source .venv/bin/activate` | `.venv\Scripts\Activate.ps1` |
| поставить pytest | `pip install -r requirements.txt` | то же |
| проверить | `pytest --version` | то же |

Если последняя команда напечатала версию pytest, окружение готово. Активировать
окружение нужно перед каждой работой: в начале строки появится `(.venv)`.

*Если PowerShell не даёт запустить `Activate.ps1`, один раз выполните
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. В cmd активация —
`.venv\Scripts\activate.bat`.*

Не каждое занятие заканчивается домашней работой в этом репозитории, поэтому
нумерация папок и нумерация занятий расходятся.

Что делать по заданию, написано в `README.md` внутри папки занятия. Там же лежат
бланки: вы вписываете свои ответы в готовую разметку. Задачу занятия
я выдаю на паре, её файлы кладите в ту же папку.

Папку для следующего занятия делаете копией предыдущей:
`cp -r lesson_03 lesson_04` (на Windows —
`Copy-Item -Recurse lesson_03 lesson_04`). Если папка занятия уже есть
в шаблоне, копировать ничего не нужно.

## Как сдавать

Одно задание — одна ветка — один Pull Request. Ветка называется по номеру
задания: `hw-01`, `hw-02`, `hw-03` и так далее.

Порядок: создать ветку, положить работу в папку задания, закоммитить,
опубликовать ветку, открыть Pull Request в свою `main`. В описании запроса
коротко пишете, что за задача, какой подход выбрали, сколько он стоит
по времени и памяти и какие тесты добавили. Сдать нужно до начала
следующего занятия.

Всё это делается кнопками в VS Code, терминал не нужен. Разбор с кадрами:

| Что нужно | Где посмотреть |
|---|---|
| создать ветку и переключиться | [ветки](docs/git/README.md#5-ветки) |
| отобрать файлы и закоммитить | [изменения и коммиты](docs/git/README.md#3-изменения-и-коммиты) |
| опубликовать ветку и открыть Pull Request | [ветки на GitHub и Pull Request](docs/git/README.md#6-ветки-на-github-и-pull-request) |
| забрать чужие правки, разобрать конфликт | [pull и fetch](docs/git/README.md#8-совместная-работа-pull-и-fetch) |

Если удобнее командами, в конце разбора есть
[шпаргалка «кнопка ↔ команда»](docs/git/README.md#шпаргалка-кнопка--команда).
Полная версия со всеми экранами — [docs/git/FULL.md](docs/git/FULL.md).

## Правила

- На тренировке ИИ можно **после собственной попытки**: review, дополнительные
  тесты, оформление текста в `.md`. Ответ проверяете запуском.
- На диагностике, mock-интервью, контестах и экзамене ИИ, поиск
  и автодополнение закрыты.
- В каждом задании отдельно написано, где модель разрешена, а где нет:
  смотрите `README.md` папки.
- Замеры, запуски и скриншоты вы делаете сами, на своём компьютере.
- Тесты должны запускаться у другого человека, который скачал ваш
  репозиторий и больше ничего не настраивал.
